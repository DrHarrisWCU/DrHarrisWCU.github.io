What is a package, and why do you need one?

In Tutorial B you saved one Python file and ran it with python3. That works for one file on one computer. ROS wants code delivered a different way, as a package. Before you make one, you should know what it is and what you get for the extra trouble.

By the end of the tutorial: you made a package, ran your Tutorial B script from it, changed the numbers, saw the same program written as a class and as a feedback loop, and you can start a new project on your own.
You already use packages

In Tutorial B you started the simulator with this command:

ros2 runturtlesimturtlesim_node

ros2 run is the command. turtlesim is the package, a bundle someone else wrote. turtlesim_node is a program inside that bundle. ROS finds the package by its name, from any folder, with no path to type. By the end of this tutorial your own script works the same way: your package has a name, your script is a program inside it, and ROS can find it.

What a package is

A package is a folder that holds three things:

  1. Your code, the Python file with your script in it.
  2. An ID card, a file called package.xml. It gives the package its name, its version, who wrote it, and which other packages it needs.
  3. Install instructions, a file called setup.py. It tells the build tool which files to copy into place and which function starts each program.

That is all. There is nothing magic in it. The wizard you will use writes the ID card and the install instructions for you, so the only file you ever type into is your own script.

Why not keep running loose files?

For one script on your own computer, a loose file is fine. Packages pay off as soon as you have a second program, a teammate, or a robot that is not your laptop.

A loose fileA package
Finding itYou must be in its folder, or type its full path.ROS finds it by name from anywhere.
Starting itOne terminal and one python3 command per file.ros2 run, and in the next tutorial one launch file that starts many programs at once.
Changing a settingEdit the file.Parameters and settings files, also in the next tutorial.
What it needsYou hope the other computer has the same libraries.package.xml lists them, and the build tool checks.
Sharing itEmail a file and hope.A folder anyone can build with one command, and other packages can depend on it.

Almost every ROS project you will find online is made of packages. To use them and to share your own, you need to be able to make one.

Workspace and build

A workspace is a folder that holds one or more packages. In this tutorial your project folder is the workspace. A build is the step that prepares a package so ROS can find it: a tool called colcon copies (or links) your files into a folder called install, which is where ROS looks. After the first build you will see three new folders beside your package: build, install and log. The build made them, so you can delete them any time and the next build makes them again.

  2. Run the wizard (turtle-nest) to make your package inside that folder.
  3. Open the folder in VS Code.
  4. Give VS Code three small files so that Ctrl+Shift+B builds and runs your package.
  5. Paste your Tutorial B script into the package.
  6. Press Ctrl+Shift+B and watch the turtle.

Teach VS Code to build and run your package

Your package is ready, but VS Code does not know how to build it or run it yet. You tell it by adding three small files to a folder named .vscode. You do this once per project, and then Ctrl+Shift+B (the three keys held down together) does the rest.

What each file does
FileWhat it is for
run.shThe list of jobs: find your package, build it, open turtlesim, run your program. A shell script is a text file of terminal commands that run one after another. It is the same list of commands you would otherwise type by hand.

Step 2 · File 1 of 3 · run.sh

  2. Move the mouse over the project name again and click the New File icon (a page with a plus sign).
  3. Type run.sh and press Enter. The file opens, empty, in the editor.
  4. Click the Copy button on the block below, click in the empty editor, and press Ctrl+V to paste.

#!/bin/bash
# This is what happens when you press Ctrl+Shift+B.
# You never need to edit this file. It finds your package, builds it, and runs it.

cd "$(dirname "$0")/.." || exit 1
source /opt/ros/humble/setup.bash

echo "== 1. Looking for your package"
PKG_XML=$(find . -maxdepth 3 -name package.xml -not -path './build/*' -not -path './install/*' | head -n 1)
if [ -z "$PKG_XML" ]; then
  echo "No package found in this folder."
  echo "Open a terminal here (Terminal menu, New Terminal), run:  turtle-nest"
  echo "Make a package, then press Ctrl+Shift+B again."
  exit 1
fi
PKG=$(basename "$(dirname "$PKG_XML")")
echo "Found package: $PKG"

echo "== 2. Building it"
colcon build --symlink-install --packages-select "$PKG" || { echo "The build failed. Read the red text above."; exit 1; }
source install/setup.bash

EXE=$(ros2 pkg executables "$PKG" | awk 'NR==1{print $2}')
if [ -z "$EXE" ]; then
  echo "The package built, but it has no program to run."
  echo "Did the wizard finish? Look for a file ending in _node.py inside the package."
  exit 1
fi

echo "== 3. Opening the turtlesim window (if needed) and clearing the old drawing"
if ! pgrep -x turtlesim_node > /dev/null; then
  setsid ros2 run turtlesim turtlesim_node > /dev/null 2>&1 &
  sleep 2
fi
ros2 service call /reset std_srvs/srv/Empty > /dev/null 2>&1 || true

echo "== 4. Running $PKG $EXE"
ros2 run "$PKG" "$EXE"

The line source /opt/ros/humble/setup.bash names the ROS release on our VM. It is the only thing in any of these files that could ever need to change, and only if your VM has a different release than Humble.

Your script · simple_draw_shape.py

"""The simple version. Make the turtle draw a shape (square, triangle, star ...) by following a plan.

Before you run this, start turtlesim in another terminal:   ros2 run turtlesim turtlesim_node
Then run this file:                                         python3 simple_draw_shape.py

How it works, in four steps:
  1. Build a PLAN. A plan is a list. Each item in the list is one instruction:
         (forward speed, turn speed, how many seconds to keep doing it)
  2. Connect to turtlesim. We make a ROS 2 node and a publisher, which is how we send messages.
  3. Wait until turtlesim is listening.
  4. Go through the plan one instruction at a time. For each instruction, send the same
     command over and over (50 times a second) until its time is up.

This is called OPEN LOOP: the program never looks at where the turtle really is.
It only watches the clock and hopes the turtle did what it was told.
"""
import math
import sys
import time

import rclpy
from geometry_msgs.msg import Twist

# ---------------- settings: change these and run again ----------------
# Which turtle to drive. Normally turtle1. To drive a second turtle, give its name when you run the
# program, for example:  python3 simple_draw_shape.py turtle2
TURTLE = sys.argv[1] if len(sys.argv) > 1 else 'turtle1'
SIDES = 4            # 3 = triangle, 4 = square, 5 = pentagon, 6 = hexagon
TURNS = 1            # 1 for an ordinary shape. SIDES = 5 with TURNS = 2 draws a five-point star
SIDE_LENGTH = 2.0    # how long each side is, in turtlesim units
SPEED = 2.0          # forward speed, in units per second
TURN_RATE = 1.0      # turning speed, in radians per second (1 radian is about 57 degrees)
SEND_EVERY = 0.02    # seconds between messages (0.02 means 50 messages a second)


def make_plan():
    """Build the plan: a list of (forward speed, turn speed, seconds) instructions."""
    plan = []                                    # start with an empty list

    # How far the turtle turns at each corner, in radians.
    # A full circle is 2 * pi radians. For a square, SIDES is 4, so each turn is a quarter circle.
    turn_angle = TURNS * 2 * math.pi / SIDES

    # Repeat once for every side. side_number counts 0, 1, 2, 3 ... but we do not need
    # its value. It is only there so the loop knows how many times to repeat.
    for side_number in range(SIDES):
        # Instruction 1: drive straight. Time = distance / speed.
        plan.append((SPEED, 0.0, SIDE_LENGTH / SPEED))
        # Instruction 2: turn on the spot. Time = angle / turn speed.
        plan.append((0.0, TURN_RATE, turn_angle / TURN_RATE))

    return plan


def main():
    # ---- Step 2: connect to ROS 2 ----
    rclpy.init()                                                  # start ROS 2
    node = rclpy.create_node('shape_drawer')                      # our program's name in ROS 2
    # A publisher sends messages to a topic. turtlesim listens on /turtle1/cmd_vel
    # for messages of type Twist (a forward speed and a turn speed). The 10 is a queue size.
    publisher = node.create_publisher(Twist, '/' + TURTLE + '/cmd_vel', 10)

    # ---- Step 3: wait until turtlesim is listening ----
    # Programs need a moment to find each other. A message sent before turtlesim is
    # connected is lost, and the first side of the shape would come out too short.
    print('Waiting for turtlesim...')
    while publisher.get_subscription_count() == 0:     # 0 means nobody is listening yet
        time.sleep(0.1)                                # wait a tenth of a second, then check again

    # ---- Step 4: follow the plan ----
    plan = make_plan()
    print('Drawing... press Ctrl+C to stop.')
    try:
        for line in plan:                              # take one instruction at a time
            forward_speed, turn_speed, seconds = line  # split the three numbers into names

            message = Twist()                          # an empty command: every value is 0.0
            message.linear.x = forward_speed           # forward speed
            message.angular.z = turn_speed             # turn speed (counter-clockwise is positive)

            # Keep sending this same command until the time is up.
            end_time = time.time() + seconds
            while time.time() < end_time:
                publisher.publish(message)
                time.sleep(SEND_EVERY)                 # pause, so we send 50 messages a second
    except KeyboardInterrupt:                          # this happens when you press Ctrl+C
        print('Stopped.')

    publisher.publish(Twist())                         # a command of all zeros means "stop"
    print('Done.')
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

    
This is the same script as in Tutorial B Module 4. If you wrote your own improved version, paste that instead. The notes at the top of the file say to run it with python3. Ignore that here, because you will use the keyboard shortcut instead.


  
The one rule: keep a function called main()
    
A file in the package called setup.py, which the wizard wrote and you never touch, contains this line:


'my_shapes_node = my_shapes.my_shapes_node:main'

    
Read it as: "to run my_shapes_node, go to the file my_shapes_node.py and call its main() function." Your file must have a function called main, or ROS has nothing to start. Your Tutorial B script has a main() at the bottom, so pasting the whole script keeps the rule. If you paste only part of a script, or delete the end, ROS stops with an ImportError that mentions main.


  
Unsaved files
    
VS Code shows a small dot on a file's tab while it has changes that are not saved. The settings.json you made saves files about a second after you stop typing, and the dot disappears. If you ever see the dot, wait a moment or press Ctrl+S. Running before the file is saved runs the old code, and the turtle does the old thing with no error. This is the most common reason for "I changed it and nothing happened."

Module 6 of 10 · about 15 minutes
The same program, written as a class

  
The placeholder the wizard wrote was a class, and so is most of the ROS code you will find online. In this module you paste the class version from Tutorial B into your package. It draws the same shape, but it is organised the way ROS programmers usually write it.

  
By the end: you have run both versions and seen that they draw the same shape, and you can say why the class version keeps its place in the plan on self.


  
Why bother, if it does the same thing?
    
You met this program at the end of Tutorial B Module 4: draw_shape.py, "the ROS way". A ROS node usually owns several things that belong together: a publisher, later subscribers, a timer, and notes about where it is in its job. A class keeps them together in one named place. There is a second reason, and it is the important one: the class version never waits inside a loop. ROS calls one method, on_timer, 50 times a second, and each call does a tiny amount of work and returns. Anything the node must remember from one call to the next, such as which line of the plan it is on, lives on self.


  
The class version · draw_shape.py

"""The ROS way: the same program as simple_draw_shape.py, written as a class with a timer.

Before you run this, start turtlesim in another terminal:   ros2 run turtlesim turtlesim_node
Then run this file:                                         python3 draw_shape.py

Most ROS 2 programs are written like this. Instead of one long function that waits, we write a
CLASS (a bundle of variables and functions that belong together) and ask ROS 2 to call one of its
functions, on_timer, 50 times a second. Each call does a tiny amount of work and returns, so ROS 2
stays free to do other things between calls.

Because on_timer runs again and again, the class remembers where it is in a variable called phase:
  'waiting'  - turtlesim is not connected yet. Check again next time.   (the first kind of waiting)
  'drawing'  - follow the plan, one line at a time.                     (the second kind of waiting)
  'finished' - everything is done.
"""
import math
import sys

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist

# ---------------- settings: change these and run again ----------------
# Which turtle to drive. Normally turtle1. To drive a second turtle, give its name when you run the
# program, for example:  python3 draw_shape.py turtle2
TURTLE = sys.argv[1] if len(sys.argv) > 1 else 'turtle1'
SIDES = 4            # 3 = triangle, 4 = square, 5 = pentagon, 6 = hexagon
TURNS = 1            # 1 for an ordinary shape. SIDES = 5 with TURNS = 2 draws a five-point star
SIDE_LENGTH = 2.0    # how long each side is, in turtlesim units
SPEED = 2.0          # forward speed, in units per second
TURN_RATE = 1.0      # turning speed, in radians per second (1 radian is about 57 degrees)
SEND_EVERY = 0.02    # seconds between messages (0.02 means 50 messages a second)


def make_plan():
    """Build the plan: a list of (forward speed, turn speed, seconds) instructions."""
    plan = []                                    # start with an empty list
    turn_angle = TURNS * 2 * math.pi / SIDES     # how far to turn at each corner, in radians
    for side_number in range(SIDES):             # repeat once per side
        plan.append((SPEED, 0.0, SIDE_LENGTH / SPEED))          # drive straight
        plan.append((0.0, TURN_RATE, turn_angle / TURN_RATE))   # turn on the spot
    return plan


class ShapeDrawer(Node):
    """A node is a program that is part of ROS 2. Putting (Node) after the name means:
    ShapeDrawer is a kind of Node, so it gets everything a Node can do (create publishers, timers ...)."""

    def __init__(self):
        """__init__ runs once, when we create a ShapeDrawer. It sets up the variables the class remembers.
        'self' means 'this ShapeDrawer'. self.plan is the plan that belongs to this one."""
        super().__init__('shape_drawer')                 # let Node do its own set-up first, and name us
        self.publisher = self.create_publisher(Twist, '/' + TURTLE + '/cmd_vel', 10)
        self.plan = make_plan()
        self.line_number = 0                             # which line of the plan we are on
        self.line_started = None                         # the time that line began
        self.phase = 'waiting'
        self.done = False
        self.timer = self.create_timer(SEND_EVERY, self.on_timer)   # call on_timer 50 times a second

    def on_timer(self):
        """ROS 2 calls this by itself, again and again. It only decides which phase we are in."""
        if self.phase == 'waiting':
            self.wait_for_turtlesim()
        elif self.phase == 'drawing':
            self.follow_plan()

    def wait_for_turtlesim(self):
        """Phase 1. Is anyone listening yet? If not, do nothing and try again next time."""
        if self.publisher.get_subscription_count() == 0:
            return                                       # not connected yet, so leave and wait for the next call
        self.line_started = self.get_clock().now()       # the first line starts now
        self.phase = 'drawing'

    def follow_plan(self):
        """Phase 2. Send the command for the current plan line. Move to the next line when its time is up."""
        now = self.get_clock().now()
        forward_speed, turn_speed, seconds = self.plan[self.line_number]
        elapsed = (now - self.line_started).nanoseconds * 1e-9     # seconds since this line began

        if elapsed >= seconds:                           # this line is finished
            self.line_number = self.line_number + 1      # move on to the next one
            self.line_started = now
            if self.line_number == len(self.plan):       # that was the last line
                self.finish()
                return
            forward_speed, turn_speed, seconds = self.plan[self.line_number]

        message = Twist()
        message.linear.x = forward_speed
        message.angular.z = turn_speed
        self.publisher.publish(message)

    def finish(self):
        self.publisher.publish(Twist())                  # all zeros means "stop"
        self.phase = 'finished'
        self.done = True
        self.get_logger().info('Done.')


def main():
    rclpy.init()
    node = ShapeDrawer()                                 # make one ShapeDrawer: this runs __init__
    try:
        while rclpy.ok() and not node.done:
            rclpy.spin_once(node)                        # let ROS 2 call on_timer when it is due
    except KeyboardInterrupt:                            # this happens when you press Ctrl+C
        node.publisher.publish(Twist())
        print('Stopped.')
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':

Module 7 of 10 · about 15 minutes
Use feedback instead of the clock

  
Both versions so far only watch the clock: drive for this many seconds, turn for that many. If a timer runs late, the error adds up and the square comes out crooked. This last version never looks at the clock. It listens to where the turtle really is, and it stops each side when the turtle has gone far enough.

  
By the end: you have run the feedback version from your package, compared its square with the open-loop square, and you can say which method is the control loop.


  
What is new
    
    
      
  • A subscription. Turtlesim publishes the turtle's position and heading, called its pose, about 60 times a second on /turtle1/pose. The line self.create_subscription(Pose, '/turtle1/pose', self.on_pose, 10) says "call my method on_pose every time one arrives."
    • 
      
  • on_pose is the whole control loop. Each time it is called it looks at the pose, decides what to do, and sends one command. There is no timer and no clock anywhere in the file.
    • 
      
  • Phases. self.phase remembers what the node is doing: 'waiting', 'driving', 'turning' or 'finished'. The pose method hands each message to the right one.
    • 
    

    
This is called closed loop: measure, compare with the goal, correct, repeat. You studied it in Tutorial B Module 5. Here you only run it as a package, and the class idea from Module 6 is what makes it tidy: the method that receives the pose and the variables it needs to remember sit together in one class.


  
The feedback version · draw_square_pose.py

"""The ROS way: the same program as simple_draw_square_pose.py, written as a class with a callback.

Before you run this, start turtlesim in another terminal:   ros2 run turtlesim turtlesim_node
Then run this file:                                         python3 draw_square_pose.py

Turtlesim publishes the turtle's pose (x, y, heading) about 60 times a second. This class
subscribes to those messages. Each time one arrives, ROS 2 calls on_pose. That one function is
the whole control loop: look at the pose, decide what to do, send a command.

The class remembers where it is in a variable called phase:
  'waiting'  - no pose has arrived yet, or turtlesim is not listening for commands yet.
  'driving'  - go forward until we have travelled SIDE_LENGTH.
  'turning'  - turn until we face the next direction.
  'finished' - everything is done.
This is CLOSED LOOP: every command is worked out from a measurement, never from a clock.
"""
import math
import sys

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist

try:
    from turtlesim_msgs.msg import Pose      # newer ROS 2 releases keep the turtlesim messages here
except ImportError:
    from turtlesim.msg import Pose           # older releases

# ---------------- settings: change these and run again ----------------
# Which turtle to drive. Normally turtle1. To drive a second turtle, give its name when you run the
# program, for example:  python3 draw_square_pose.py turtle2
TURTLE = sys.argv[1] if len(sys.argv) > 1 else 'turtle1'
SIDES = 4                # 3 = triangle, 4 = square, 6 = hexagon ...
SIDE_LENGTH = 2.0        # units
MAX_SPEED = 2.0          # fastest forward speed, units per second
MAX_TURN = 2.0           # fastest turning speed, radians per second
SPEED_PER_UNIT = 3.0     # drive speed = this x the distance still to go, so it slows down near the goal
TURN_PER_RADIAN = 4.0    # turn speed = this x the angle still to turn
MIN_SPEED = 0.15         # never slower than this, or the turtle would crawl for ever
MIN_TURN = 0.1
DISTANCE_OK = 0.02       # close enough to the end of the side, in units
ANGLE_OK = 0.01          # close enough to the new heading, in radians


def wrap(angle):
    """Turn any angle into the range -pi to +pi, the same range the turtle reports.
    Without this, a heading of +3.1 and a goal of -3.1 would look 6.2 radians apart
    when they are really only 0.08 radians apart."""
    return angle - 2 * math.pi * math.floor((angle + math.pi) / (2 * math.pi))


class SquareDrawer(Node):
    """A node is a program that is part of ROS 2. SquareDrawer is a kind of Node."""

    def __init__(self):
        """__init__ runs once, when we create a SquareDrawer. 'self' means 'this SquareDrawer'."""
        super().__init__('square_drawer')                # let Node do its own set-up first, and name us
        self.publisher = self.create_publisher(Twist, '/' + TURTLE + '/cmd_vel', 10)
        self.subscription = self.create_subscription(Pose, '/' + TURTLE + '/pose', self.on_pose, 10)
        self.phase = 'waiting'
        self.side_number = 0         # how many sides are finished
        self.start_x = 0.0           # where the current side began
        self.start_y = 0.0
        self.goal_heading = 0.0      # the direction the turtle should face
        self.done = False

    def on_pose(self, pose):
        """ROS 2 calls this by itself every time a Pose message arrives. 'pose' is that message."""
        if self.phase == 'waiting':
            self.wait_for_turtlesim(pose)
        elif self.phase == 'driving':
            self.drive(pose)
        elif self.phase == 'turning':
            self.turn(pose)

    def wait_for_turtlesim(self, pose):
        """Phase 1. A pose has arrived. Is turtlesim also listening for commands?"""
        if self.publisher.get_subscription_count() == 0:
            return                                       # not yet: wait for the next pose
        self.goal_heading = pose.theta                   # start from the way the turtle already faces
        self.begin_side(pose)

    def begin_side(self, pose):
        """Remember where this side starts, and switch to driving."""
        self.start_x = pose.x
        self.start_y = pose.y
        self.phase = 'driving'

    def drive(self, pose):
        """Phase 2. Go forward until we have travelled SIDE_LENGTH."""
        travelled = math.hypot(pose.x - self.start_x, pose.y - self.start_y)
        remaining = SIDE_LENGTH - travelled
        if remaining <= DISTANCE_OK:                     # far enough: time to turn
            self.goal_heading = wrap(self.goal_heading + 2 * math.pi / SIDES)
            self.phase = 'turning'
            return
        message = Twist()
        speed = SPEED_PER_UNIT * remaining               # far away = fast, nearly there = slow
        message.linear.x = min(MAX_SPEED, max(MIN_SPEED, speed))
        self.publisher.publish(message)

    def turn(self, pose):
        """Phase 3. Turn until the turtle faces the next direction."""
        error = wrap(self.goal_heading - pose.theta)     # how far we still have to turn (+ or -)
        if abs(error) < ANGLE_OK:                        # facing the right way
            self.side_number = self.side_number + 1
            if self.side_number == SIDES:
                self.finish()
            else:
                self.begin_side(pose)
            return
        message = Twist()
        rate = min(MAX_TURN, max(MIN_TURN, TURN_PER_RADIAN * abs(error)))
        message.angular.z = math.copysign(rate, error)   # turn toward the goal, either way
        self.publisher.publish(message)

    def finish(self):
        self.publisher.publish(Twist())                  # all zeros means "stop"
        self.phase = 'finished'
        self.done = True
        self.get_logger().info('Done.')


def main():
    rclpy.init()
    node = SquareDrawer()                                # make one SquareDrawer: this runs __init__
    try:
        while rclpy.ok() and not node.done:
            rclpy.spin_once(node)                        # let ROS 2 call on_pose when a pose arrives
    except KeyboardInterrupt:                            # this happens when you press Ctrl+C
        node.publisher.publish(Twist())
        print('Stopped.')
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

When it goes wrong

  
Sooner or later the panel prints something you did not expect. That is normal for everyone who writes code. The skill is knowing which kind of trouble you have, and where to look first.

  
By the end: you can sort a problem into one of three kinds and name the first thing to check for each.

What you seeWhat it meansLook first

      
Our own message, such as No package found in this folder, or The build failedThe run script stopped before your code ran.Read the line that says what to do. For a failed build, read the first red line above it.

      
A block of text starting Traceback, or a SyntaxErrorYour Python code has a mistake.Read the last line first: it names the problem. The line above it gives the file and the line number.

A habit that saves hours
    
Change one thing, then press Ctrl+Shift+B. If you changed six things and it breaks, you have six suspects. If you changed one, you have one. When you are stuck, undo your last change with Ctrl+Z and check that the program works again before you try something else.

Why one project per workspace?
    
Every project gets its own folder. That keeps projects from interfering with each other: a package in one cannot break a package in another, and you can delete a project by deleting its folder. It also means that "which package do I run?" always has one answer, because there is only one in the folder. The run script relies on that: it builds the first package it finds.

package.xml
The package's ID card: its name, version, who made it, and what it needs.

Tells the build tool which files to install and links your program's name to its main().

Two small bookkeeping pieces that let ROS find the package.

      
test/
Automatic style checks. Ignore them for now.

      
config/ and launch/
Only if you ticked them. The settings file and the start-everything recipe. They are the next tutorial.

      
build/, install/, log/
Made by the build. Generated, so you can delete them any time and the next Ctrl+Shift+B makes them again.
