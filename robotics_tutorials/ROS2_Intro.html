Get the ROS 2 virtual machine running

ROS 2 is installed and ready inside a virtual machine: a whole second computer that runs in a window on yours. You download it once, unpack it, and open it in VirtualBox. Everything you need is already on it, so there is nothing to install inside.

By the end: the lab's ROS 2 desktop is running in a window, you can get your mouse back from it, and you have two terminals open side by side.
Before you start

You need a Windows or Linux computer with VirtualBox installed, a download of tens of gigabytes, and room on the disk: the unpacked machine is about 50 GB, and the downloaded pieces sit beside it, so plan for about 100 GB free until you delete the pieces. Apple-silicon Macs (M1 and later) cannot run this kind of machine in VirtualBox. If that is you, use a lab computer or ask your instructor.

  1. Install 7-Zip. The VM arrives as a split archive and the tool that unpacks it is the free 7-Zip. Install it and keep the default options.
  2. Show file extensions. In File Explorer open the View menu, then Show, and tick File name extensions. You need to see the end of each file name to pick the right file in step 4.
  3. Download every file in the folder. The machine is cut into pieces with names ending .zip.001, .zip.002, and so on. Put all of them in one new folder. If one is missing, the unpacking fails near the end. Your instructor will give you the link to the folder.
  4. Unpack it. Right-click only the first file, the one ending .zip.001, choose 7-Zip, then Extract Here. Do not extract the others. 7-Zip finds the rest by itself because they sit in the same folder. This takes a while.
  5. Import it into VirtualBox. Open VirtualBox, choose Machine and then Add (some versions call it Open), and pick the VM file from the unpacked folder. If you were given an .ova file instead, use File then Import Appliance.
  6. Give it the right amount of computer. Select the machine and open Settings. Under System, move the Base Memory slider and the Processors slider, and keep both in the green part of the bar. Under System, Acceleration, turn on the hardware acceleration options. Under Display, raise Video Memory to the maximum.
  7. Start it and sign in. Select the machine and press Start. Your instructor will tell you the user name and password for the desktop.
  8. Learn the host key. The VM captures your mouse and keyboard when you click inside it. To get them back, press the host key, which is the right Ctrl key by default. VirtualBox shows the host key in the bottom right corner of its window.
  9. Optional: Guest Additions. In the VM's menu choose Devices then Insert Guest Additions CD image and follow the installer. This gives you drag-and-drop of files and a shared clipboard (also under Devices) so you can copy a command on this page and paste it into the VM.

Module 2 of 7 · about 30 minutes

Nodes, topics and messages

A ROS 2 robot is not one big program. It is many small programs, called nodes, that each do one job and pass messages to each other along named channels called topics. Turtlesim is one node. The keyboard controller is another. They never talk to each other directly. They both talk to a topic.

By the end: you can name the node, topic and message in the turtle demo, and use four ros2 commands to look inside a running system.
Four words

Node: a running program that is part of the system. Topic: a named channel, like /turtle1/cmd_vel. Message: one piece of data sent on a topic, with a fixed layout called its type. Publish and subscribe: a node that sends on a topic publishes, and a node that listens subscribes. Neither needs to know who is at the other end.

What is inside a Twist

The command message is geometry_msgs/msg/Twist. A twist is a velocity, in two parts: linear (how fast it moves along x, y and z) and angular (how fast it turns about x, y and z). A turtle on a flat floor uses only linear.x, the forward speed, and angular.z, the turn rate. The other four numbers are ignored. Speeds are per second: units per second for linear, radians per second for angular.

Turtlesim answers with a second message, turtlesim/msg/Pose: its x, y, heading (theta, in radians) and current speeds. Module 5 uses that feedback. On newer ROS 2 releases the turtle messages may be named turtlesim_msgs/msg/.... Your VM tells you the real name when you run ros2 topic list -t.

Module 3 of 7 · about 35 minutes

Drive the turtle with commands you type

The teleop is only a node that publishes Twist messages when you press a key. You can publish the same messages yourself from the terminal. That is the fastest way to test a robot: send exactly the message you want and watch what happens. This module also meets the two other kinds of conversation ROS 2 has, services and actions.

By the end: you can move the turtle with ros2 topic pub, explain why it stops by itself, and use a service to clear the screen and lift the pen.
ros2 topic pub 
ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0}}"
ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{angular: {z: 1.5708}}"
ros2 topic pub -r 1 /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0}, angular: {z: 1.0}}"

The pieces are: the topic name, the message type, and the message written as YAML inside double quotes. Fields you leave out are zero. --once sends one message and stops. -r 1 sends one every second until you press Ctrl+C.

YAML is picky about one thing: after each colon you need a space. {x: 2.0} works. {x:2.0} does not.

Why does the turtle stop by itself?

Turtlesim obeys the last command it received and forgets it after one second without a new one. So --once with a forward speed of 2 moves the turtle about 2 units, then it stops. A safe habit for real robots too: a robot that stops when it hears nothing is a robot that does not run away.

A fast repeating message therefore gives continuous motion. A forward speed of 2 together with a turn rate of 1 for as long as you keep sending makes a circle of radius 2 (radius = speed / turn rate).

Write a node that draws a shape

Typing commands one at a time does not scale. A node is a Python program that does the publishing for you, following a plan. You will read a short one, run it in the VM, and then change it to draw shapes of your own. The plan is a list of lines. Each line says: go this fast forward, turn this fast, for this many seconds.

By the end: you can run simple_draw_shape.py, explain each part of it, make it draw a square, a hexagon and a five-point star, and read the same program written as a class.
The script

This is the simple version: one function, plain loops, no classes. Copy it into a file called simple_draw_shape.py in the VM (open Sublime Text or VS Code, paste, save). Start turtlesim in one Terminator pane. Then in another pane, in the folder that holds the file, run python3 simple_draw_shape.py.

"""The simple version. Make the turtle draw a shape (square, triangle, star ...) by following a plan.

Before you run this, start turtlesim in another terminal:   ros2 run turtlesim turtlesim_node
Then run this file:                                         python3 simple_draw_shape.py

How it works, in four steps:
  1. Build a PLAN. A plan is a list. Each item in the list is one instruction:
         (forward speed, turn speed, how many seconds to keep doing it)
  2. Connect to turtlesim. We make a ROS 2 node and a publisher, which is how we send messages.
  3. Wait until turtlesim is listening.
  4. Go through the plan one instruction at a time. For each instruction, send the same
     command over and over (50 times a second) until its time is up.

This is called OPEN LOOP: the program never looks at where the turtle really is.
It only watches the clock and hopes the turtle did what it was told.
"""
import math
import sys
import time

import rclpy
from geometry_msgs.msg import Twist

# ---------------- settings: change these and run again ----------------
# Which turtle to drive. Normally turtle1. To drive a second turtle, give its name when you run the
# program, for example:  python3 simple_draw_shape.py turtle2
TURTLE = sys.argv[1] if len(sys.argv) > 1 else 'turtle1'
SIDES = 4            # 3 = triangle, 4 = square, 5 = pentagon, 6 = hexagon
TURNS = 1            # 1 for an ordinary shape. SIDES = 5 with TURNS = 2 draws a five-point star
SIDE_LENGTH = 2.0    # how long each side is, in turtlesim units
SPEED = 2.0          # forward speed, in units per second
TURN_RATE = 1.0      # turning speed, in radians per second (1 radian is about 57 degrees)
SEND_EVERY = 0.02    # seconds between messages (0.02 means 50 messages a second)


def make_plan():
    """Build the plan: a list of (forward speed, turn speed, seconds) instructions."""
    plan = []                                    # start with an empty list

    # How far the turtle turns at each corner, in radians.
    # A full circle is 2 * pi radians. For a square, SIDES is 4, so each turn is a quarter circle.
    turn_angle = TURNS * 2 * math.pi / SIDES

    # Repeat once for every side. side_number counts 0, 1, 2, 3 ... but we do not need
    # its value. It is only there so the loop knows how many times to repeat.
    for side_number in range(SIDES):
        # Instruction 1: drive straight. Time = distance / speed.
        plan.append((SPEED, 0.0, SIDE_LENGTH / SPEED))
        # Instruction 2: turn on the spot. Time = angle / turn speed.
        plan.append((0.0, TURN_RATE, turn_angle / TURN_RATE))

    return plan


def main():
    # ---- Step 2: connect to ROS 2 ----
    rclpy.init()                                                  # start ROS 2
    node = rclpy.create_node('shape_drawer')                      # our program's name in ROS 2
    # A publisher sends messages to a topic. turtlesim listens on /turtle1/cmd_vel
    # for messages of type Twist (a forward speed and a turn speed). The 10 is a queue size.
    publisher = node.create_publisher(Twist, '/' + TURTLE + '/cmd_vel', 10)

    # ---- Step 3: wait until turtlesim is listening ----
    # Programs need a moment to find each other. A message sent before turtlesim is
    # connected is lost, and the first side of the shape would come out too short.
    print('Waiting for turtlesim...')
    while publisher.get_subscription_count() == 0:     # 0 means nobody is listening yet
        time.sleep(0.1)                                # wait a tenth of a second, then check again

    # ---- Step 4: follow the plan ----
    plan = make_plan()
    print('Drawing... press Ctrl+C to stop.')
    try:
        for line in plan:                              # take one instruction at a time
            forward_speed, turn_speed, seconds = line  # split the three numbers into names

            message = Twist()                          # an empty command: every value is 0.0
            message.linear.x = forward_speed           # forward speed
            message.angular.z = turn_speed             # turn speed (counter-clockwise is positive)

            # Keep sending this same command until the time is up.
            end_time = time.time() + seconds
            while time.time() < end_time:
                publisher.publish(message)
                time.sleep(SEND_EVERY)                 # pause, so we send 50 messages a second
    except KeyboardInterrupt:                          # this happens when you press Ctrl+C
        print('Stopped.')

    publisher.publish(Twist())                         # a command of all zeros means "stop"
    print('Done.')
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()
Reading it, part by part

What is rclpy? The name is short for ROS Client Library for Python. ROS 2 itself is built in C and C++ underneath. A client library is the doorway that lets a program in another language join the same network of nodes and topics that the ros2 terminal commands use. There is a C++ version called rclcpp. Three calls matter in this script: rclpy.init() connects your program to ROS 2, rclpy.create_node('shape_drawer') gives it a name, and rclpy.shutdown() disconnects. Prove it to yourself: while the script runs, type ros2 node list in a third terminal and look for /shape_drawer.

The header. The long comment at the top (between the triple quotes) says what the program does in four steps. Read it first. Every program should start that way.

Imports. rclpy is the ROS 2 library for Python. Twist is the message type: a forward speed and a turn speed. time lets the program wait.

Settings. All the numbers you will want to change sit at the top, with names. SIDES = 5 with TURNS = 2 makes the turn at each corner 2 × 360° / 5 = 144°, which joins every second corner and draws a star.

make_plan. plan = [] makes an empty list, like an empty shopping list. The for loop repeats once per side, and each time round plan.append(...) adds one item to the end of the list: first a forward line, then a turn line. The turn time is the angle divided by the turn rate. Try it by hand: a 90° corner is 1.5708 radians, and at 1 rad/s that takes 1.5708 seconds.

Step 2 in main: connect. create_node gives your program a name inside ROS 2. create_publisher(Twist, '/turtle1/cmd_vel', 10) makes the sending end of the topic from Module 2. The 10 is a queue size. You do not need to write a class for any of this.

Step 3: wait for turtlesim (the first kind of waiting). Programs need a moment to find each other. A message sent before turtlesim is connected is lost, which would make the first side too short. This loop asks get_subscription_count() again and again, with a short sleep between asks, until someone is listening. It happens once, before anything is drawn.

Step 4: follow the plan (the second kind of waiting). The outer for loop takes one line of the plan at a time. The inner while loop sends that line's command 50 times a second until its seconds are used up, then the outer loop moves on to the next line. This waiting happens once per line, all the way through the shape. An all-zero Twist at the end stops the turtle.

The ROS way: the same program as a class
    
The simple version works, but almost every ROS 2 program you will read online is written differently: as a class. You need to be able to read that style, so here is the same program rewritten in it. It draws exactly the same shape.

    
A class in four ideas.

    
    
      
  1. A class bundles variables and functions that belong together. Our ShapeDrawer keeps its plan, its place in the plan and its phase together, with the functions that use them. Functions that live inside a class are called methods.
    2. 
      
  2. self means "this one". Inside a method, self.plan is the plan belonging to this ShapeDrawer. Variables that start with self. are remembered between calls. Ordinary variables inside a method are forgotten when it ends.
    3. 
      
  3. __init__ runs once, when the object is made. The line node = ShapeDrawer() in main makes one ShapeDrawer and runs its __init__ to set everything up.
    4. 
      
  4. (Node) after the class name means "is a kind of Node". The class inherits everything a ROS node can do, such as create_publisher and create_timer. The line super().__init__('shape_drawer') lets Node do its own set-up and gives the node its name.
    5. 
    

    
Why do ROS programs do it this way? In the simple version the program does the waiting itself with time.sleep, and nothing else can run in the meantime. In the class version ROS 2 does the waiting. You hand it a function with create_timer(SEND_EVERY, self.on_timer), and it calls on_timer 50 times a second. A function that ROS calls for you like this is called a callback. Each call must do a little work and return quickly. Because the function starts from scratch each time, the object has to remember where it is, and that is what self.phase and self.line_number are for.

"""The ROS way: the same program as simple_draw_shape.py, written as a class with a timer.

Before you run this, start turtlesim in another terminal:   ros2 run turtlesim turtlesim_node
Then run this file:                                         python3 draw_shape.py

Most ROS 2 programs are written like this. Instead of one long function that waits, we write a
CLASS (a bundle of variables and functions that belong together) and ask ROS 2 to call one of its
functions, on_timer, 50 times a second. Each call does a tiny amount of work and returns, so ROS 2
stays free to do other things between calls.

Because on_timer runs again and again, the class remembers where it is in a variable called phase:
  'waiting'  - turtlesim is not connected yet. Check again next time.   (the first kind of waiting)
  'drawing'  - follow the plan, one line at a time.                     (the second kind of waiting)
  'finished' - everything is done.
"""
import math
import sys

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist

# ---------------- settings: change these and run again ----------------
# Which turtle to drive. Normally turtle1. To drive a second turtle, give its name when you run the
# program, for example:  python3 draw_shape.py turtle2
TURTLE = sys.argv[1] if len(sys.argv) > 1 else 'turtle1'
SIDES = 4            # 3 = triangle, 4 = square, 5 = pentagon, 6 = hexagon
TURNS = 1            # 1 for an ordinary shape. SIDES = 5 with TURNS = 2 draws a five-point star
SIDE_LENGTH = 2.0    # how long each side is, in turtlesim units
SPEED = 2.0          # forward speed, in units per second
TURN_RATE = 1.0      # turning speed, in radians per second (1 radian is about 57 degrees)
SEND_EVERY = 0.02    # seconds between messages (0.02 means 50 messages a second)


def make_plan():
    """Build the plan: a list of (forward speed, turn speed, seconds) instructions."""
    plan = []                                    # start with an empty list
    turn_angle = TURNS * 2 * math.pi / SIDES     # how far to turn at each corner, in radians
    for side_number in range(SIDES):             # repeat once per side
        plan.append((SPEED, 0.0, SIDE_LENGTH / SPEED))          # drive straight
        plan.append((0.0, TURN_RATE, turn_angle / TURN_RATE))   # turn on the spot
    return plan


class ShapeDrawer(Node):
    """A node is a program that is part of ROS 2. Putting (Node) after the name means:
    ShapeDrawer is a kind of Node, so it gets everything a Node can do (create publishers, timers ...)."""

    def __init__(self):
        """__init__ runs once, when we create a ShapeDrawer. It sets up the variables the class remembers.
        'self' means 'this ShapeDrawer'. self.plan is the plan that belongs to this one."""
        super().__init__('shape_drawer')                 # let Node do its own set-up first, and name us
        self.publisher = self.create_publisher(Twist, '/' + TURTLE + '/cmd_vel', 10)
        self.plan = make_plan()
        self.line_number = 0                             # which line of the plan we are on
        self.line_started = None                         # the time that line began
        self.phase = 'waiting'
        self.done = False
        self.timer = self.create_timer(SEND_EVERY, self.on_timer)   # call on_timer 50 times a second

    def on_timer(self):
        """ROS 2 calls this by itself, again and again. It only decides which phase we are in."""
        if self.phase == 'waiting':
            self.wait_for_turtlesim()
        elif self.phase == 'drawing':
            self.follow_plan()

    def wait_for_turtlesim(self):
        """Phase 1. Is anyone listening yet? If not, do nothing and try again next time."""
        if self.publisher.get_subscription_count() == 0:
            return                                       # not connected yet, so leave and wait for the next call
        self.line_started = self.get_clock().now()       # the first line starts now
        self.phase = 'drawing'

    def follow_plan(self):
        """Phase 2. Send the command for the current plan line. Move to the next line when its time is up."""
        now = self.get_clock().now()
        forward_speed, turn_speed, seconds = self.plan[self.line_number]
        elapsed = (now - self.line_started).nanoseconds * 1e-9     # seconds since this line began

        if elapsed >= seconds:                           # this line is finished
            self.line_number = self.line_number + 1      # move on to the next one
            self.line_started = now
            if self.line_number == len(self.plan):       # that was the last line
                self.finish()
                return
            forward_speed, turn_speed, seconds = self.plan[self.line_number]

        message = Twist()
        message.linear.x = forward_speed
        message.angular.z = turn_speed
        self.publisher.publish(message)

    def finish(self):
        self.publisher.publish(Twist())                  # all zeros means "stop"
        self.phase = 'finished'
        self.done = True
        self.get_logger().info('Done.')


def main():
    rclpy.init()
    node = ShapeDrawer()                                 # make one ShapeDrawer: this runs __init__
    try:
        while rclpy.ok() and not node.done:
            rclpy.spin_once(node)                        # let ROS 2 call on_timer when it is due
    except KeyboardInterrupt:                            # this happens when you press Ctrl+C
        node.publisher.publish(Twist())
        print('Stopped.')
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

    
Where did the two kinds of waiting go? They are now two separate methods. wait_for_turtlesim runs while the phase is 'waiting', and once someone is listening it switches the phase to 'drawing'. follow_plan runs while the phase is 'drawing': it works out how long the current line has run, moves to the next line when the time is up, and publishes. on_timer only decides which of the two to call.

    
Which should you write? For a short program like this, the simple one is easier to read. For anything that has to do several things at once, such as listen to sensors, publish commands and answer service calls, the class style is how ROS 2 is meant to be used, and every official tutorial uses it.


  
What would a skeptical reviewer say?
    
"Your square does not quite close." True, and that is the point of Module 5. In a virtual machine the shape can come out tilted, with sides a little different and the end short of the start. That is normal for this script. Waiting with time.sleep always comes back a little late, a few to a few tens of milliseconds on a busy VM, and the plan counts seconds, not distance or angle. Each late tick adds a small error that is never corrected. Hold that thought.

Module 5 of 7 · about 40 minutes
Close the loop: listen to the pose

  
The last script follows the clock and hopes. If a command arrives a little late, the turtle goes a little further or turns a little less, and the error stays in the drawing. A robot that can measure what it did can correct itself. Turtlesim publishes its pose, so a node can subscribe to it, compare the pose with the goal, and send a command that shrinks the difference. That is a closed loop, and it is the idea behind every controller.

  
By the end: you can explain the difference between open and closed loop, run simple_draw_square_pose.py, read the class version, and say when feedback is worth its extra code.

"""The simple version. Make the turtle draw a shape by LISTENING to where it is, instead of watching the clock.

Before you run this, start turtlesim in another terminal:   ros2 run turtlesim turtlesim_node
Then run this file:                                         python3 simple_draw_square_pose.py

Turtlesim keeps telling everyone where the turtle is: about 60 times a second it publishes
a Pose message (x, y and heading) on the topic /turtle1/pose. This program subscribes to
that topic. For every side of the shape it does two jobs:
  - DRIVE: keep checking how far the turtle has travelled, and stop when it is far enough.
  - TURN:  keep checking which way the turtle faces, and stop when it faces the new direction.

This is called CLOSED LOOP: measure, compare with the goal, correct, repeat.
Because we never count time, a late timer cannot add up to a crooked shape.
"""
import math
import sys

import rclpy
from geometry_msgs.msg import Twist

try:
    from turtlesim_msgs.msg import Pose      # newer ROS 2 releases keep the turtlesim messages here
except ImportError:
    from turtlesim.msg import Pose           # older releases

# ---------------- settings: change these and run again ----------------
# Which turtle to drive. Normally turtle1. To drive a second turtle, give its name when you run the
# program, for example:  python3 simple_draw_square_pose.py turtle2
TURTLE = sys.argv[1] if len(sys.argv) > 1 else 'turtle1'
SIDES = 4                # 3 = triangle, 4 = square, 6 = hexagon ...
SIDE_LENGTH = 2.0        # units
MAX_SPEED = 2.0          # fastest forward speed, units per second
MAX_TURN = 2.0           # fastest turning speed, radians per second
SPEED_PER_UNIT = 3.0     # drive speed = this x the distance still to go, so it slows down near the goal
TURN_PER_RADIAN = 4.0    # turn speed = this x the angle still to turn
MIN_SPEED = 0.15         # never slower than this, or the turtle would crawl for ever
MIN_TURN = 0.1
DISTANCE_OK = 0.02       # close enough to the end of the side, in units
ANGLE_OK = 0.01          # close enough to the new heading, in radians

latest_pose = None       # the newest Pose message we have received (None until the first one arrives)


def on_pose(message):
    """ROS calls this function by itself every time a new Pose message arrives."""
    global latest_pose                # "global" lets this function change the variable above
    latest_pose = message


def wrap(angle):
    """Turn any angle into the range -pi to +pi, the same range the turtle reports.
    Without this, a heading of +3.1 and a goal of -3.1 would look 6.2 radians apart
    when they are really only 0.08 radians apart."""
    return angle - 2 * math.pi * math.floor((angle + math.pi) / (2 * math.pi))


def main():
    rclpy.init()
    node = rclpy.create_node('square_drawer')
    publisher = node.create_publisher(Twist, '/' + TURTLE + '/cmd_vel', 10)
    node.create_subscription(Pose, '/' + TURTLE + '/pose', on_pose, 10)   # call on_pose for every pose message

    def read_pose():
        """Wait for ROS to deliver a message (up to 0.1 s), then return the newest pose."""
        rclpy.spin_once(node, timeout_sec=0.1)
        return latest_pose

    # Wait for the first pose, so we know where the turtle starts and which way it faces.
    print('Waiting for turtlesim...')
    pose = None
    while pose is None:
        pose = read_pose()
    while publisher.get_subscription_count() == 0:    # also make sure turtlesim is listening for commands
        pose = read_pose()
    goal_heading = pose.theta         # the direction the next side should point in

    print('Drawing... press Ctrl+C to stop.')
    try:
        for side_number in range(SIDES):             # once per side (side_number is only a counter)

            # ---- DRIVE forward until we have gone SIDE_LENGTH ----
            start_x, start_y = pose.x, pose.y        # remember where this side began
            while True:
                pose = read_pose()
                travelled = math.hypot(pose.x - start_x, pose.y - start_y)
                remaining = SIDE_LENGTH - travelled
                if remaining <= DISTANCE_OK:
                    break                            # far enough: leave the drive loop
                message = Twist()
                speed = SPEED_PER_UNIT * remaining   # far away = fast, nearly there = slow
                message.linear.x = min(MAX_SPEED, max(MIN_SPEED, speed))
                publisher.publish(message)

            # ---- TURN until the turtle faces the next direction ----
            goal_heading = wrap(goal_heading + 2 * math.pi / SIDES)
            while True:
                pose = read_pose()
                error = wrap(goal_heading - pose.theta)   # how far we still have to turn (+ or -)
                if abs(error) < ANGLE_OK:
                    break                            # facing the right way: leave the turn loop
                message = Twist()
                rate = TURN_PER_RADIAN * abs(error)
                rate = min(MAX_TURN, max(MIN_TURN, rate))
                message.angular.z = math.copysign(rate, error)   # turn toward the goal, either way
                publisher.publish(message)
    except KeyboardInterrupt:                        # this happens when you press Ctrl+C
        print('Stopped.')

    publisher.publish(Twist())                       # all zeros means "stop"
    print('Done.')
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()


  
What changed
    
A subscription instead of a clock. create_subscription(Pose, '/turtle1/pose', on_pose, 10) asks ROS 2 to call the function on_pose each time a pose message arrives, about 60 times a second. It stores the newest pose in latest_pose. The program never looks at a clock.

    
Two loops per side. For every side the program runs a drive loop and then a turn loop. In the drive loop it measures the distance from where the side began and leaves the loop when it is within DISTANCE_OK. In the turn loop it compares the heading with the goal heading and leaves when it is within ANGLE_OK. Each loop ends because of a measurement, not because time ran out.

    
Proportional control. The command is proportional to the error: speed = SPEED_PER_UNIT × distance still to go, capped at MAX_SPEED. Far away, it runs flat out. Near the goal, it slows down, which stops it overshooting. The minimum speed stops it creeping for ever.

    
wrap(). Headings jump from +π to −π. Without wrapping, a goal of −3.1 and a heading of +3.1 looks like an error of 6.2 radians instead of 0.08, and the turtle spins the long way round.


  
The ROS way: the same program as a class
    
As in Module 4, here is the same closed-loop program written the way ROS 2 code is usually written. Two things are new. The callback is a method, self.on_pose, and the loop disappears: ROS 2 calls on_pose every time a pose arrives, so that one method is the control loop. And the two while True loops become two phases, 'driving' and 'turning', stored in self.phase, because the method has to remember between calls which job it is doing. Save it as draw_square_pose.py.


"""The ROS way: the same program as simple_draw_square_pose.py, written as a class with a callback.

Before you run this, start turtlesim in another terminal:   ros2 run turtlesim turtlesim_node
Then run this file:                                         python3 draw_square_pose.py

Turtlesim publishes the turtle's pose (x, y, heading) about 60 times a second. This class
subscribes to those messages. Each time one arrives, ROS 2 calls on_pose. That one function is
the whole control loop: look at the pose, decide what to do, send a command.

The class remembers where it is in a variable called phase:
  'waiting'  - no pose has arrived yet, or turtlesim is not listening for commands yet.
  'driving'  - go forward until we have travelled SIDE_LENGTH.
  'turning'  - turn until we face the next direction.
  'finished' - everything is done.
This is CLOSED LOOP: every command is worked out from a measurement, never from a clock.
"""
import math
import sys

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist

try:
    from turtlesim_msgs.msg import Pose      # newer ROS 2 releases keep the turtlesim messages here
except ImportError:
    from turtlesim.msg import Pose           # older releases

# ---------------- settings: change these and run again ----------------
# Which turtle to drive. Normally turtle1. To drive a second turtle, give its name when you run the
# program, for example:  python3 draw_square_pose.py turtle2
TURTLE = sys.argv[1] if len(sys.argv) > 1 else 'turtle1'
SIDES = 4                # 3 = triangle, 4 = square, 6 = hexagon ...
SIDE_LENGTH = 2.0        # units
MAX_SPEED = 2.0          # fastest forward speed, units per second
MAX_TURN = 2.0           # fastest turning speed, radians per second
SPEED_PER_UNIT = 3.0     # drive speed = this x the distance still to go, so it slows down near the goal
TURN_PER_RADIAN = 4.0    # turn speed = this x the angle still to turn
MIN_SPEED = 0.15         # never slower than this, or the turtle would crawl for ever
MIN_TURN = 0.1
DISTANCE_OK = 0.02       # close enough to the end of the side, in units
ANGLE_OK = 0.01          # close enough to the new heading, in radians


def wrap(angle):
    """Turn any angle into the range -pi to +pi, the same range the turtle reports.
    Without this, a heading of +3.1 and a goal of -3.1 would look 6.2 radians apart
    when they are really only 0.08 radians apart."""
    return angle - 2 * math.pi * math.floor((angle + math.pi) / (2 * math.pi))


class SquareDrawer(Node):
    """A node is a program that is part of ROS 2. SquareDrawer is a kind of Node."""

    def __init__(self):
        """__init__ runs once, when we create a SquareDrawer. 'self' means 'this SquareDrawer'."""
        super().__init__('square_drawer')                # let Node do its own set-up first, and name us
        self.publisher = self.create_publisher(Twist, '/' + TURTLE + '/cmd_vel', 10)
        self.subscription = self.create_subscription(Pose, '/' + TURTLE + '/pose', self.on_pose, 10)
        self.phase = 'waiting'
        self.side_number = 0         # how many sides are finished
        self.start_x = 0.0           # where the current side began
        self.start_y = 0.0
        self.goal_heading = 0.0      # the direction the turtle should face
        self.done = False

    def on_pose(self, pose):
        """ROS 2 calls this by itself every time a Pose message arrives. 'pose' is that message."""
        if self.phase == 'waiting':
            self.wait_for_turtlesim(pose)
        elif self.phase == 'driving':
            self.drive(pose)
        elif self.phase == 'turning':
            self.turn(pose)

    def wait_for_turtlesim(self, pose):
        """Phase 1. A pose has arrived. Is turtlesim also listening for commands?"""
        if self.publisher.get_subscription_count() == 0:
            return                                       # not yet: wait for the next pose
        self.goal_heading = pose.theta                   # start from the way the turtle already faces
        self.begin_side(pose)

    def begin_side(self, pose):
        """Remember where this side starts, and switch to driving."""
        self.start_x = pose.x
        self.start_y = pose.y
        self.phase = 'driving'

    def drive(self, pose):
        """Phase 2. Go forward until we have travelled SIDE_LENGTH."""
        travelled = math.hypot(pose.x - self.start_x, pose.y - self.start_y)
        remaining = SIDE_LENGTH - travelled
        if remaining <= DISTANCE_OK:                     # far enough: time to turn
            self.goal_heading = wrap(self.goal_heading + 2 * math.pi / SIDES)
            self.phase = 'turning'
            return
        message = Twist()
        speed = SPEED_PER_UNIT * remaining               # far away = fast, nearly there = slow
        message.linear.x = min(MAX_SPEED, max(MIN_SPEED, speed))
        self.publisher.publish(message)

    def turn(self, pose):
        """Phase 3. Turn until the turtle faces the next direction."""
        error = wrap(self.goal_heading - pose.theta)     # how far we still have to turn (+ or -)
        if abs(error) < ANGLE_OK:                        # facing the right way
            self.side_number = self.side_number + 1
            if self.side_number == SIDES:
                self.finish()
            else:
                self.begin_side(pose)
            return
        message = Twist()
        rate = min(MAX_TURN, max(MIN_TURN, TURN_PER_RADIAN * abs(error)))
        message.angular.z = math.copysign(rate, error)   # turn toward the goal, either way
        self.publisher.publish(message)

    def finish(self):
        self.publisher.publish(Twist())                  # all zeros means "stop"
        self.phase = 'finished'
        self.done = True
        self.get_logger().info('Done.')


def main():
    rclpy.init()
    node = SquareDrawer()                                # make one SquareDrawer: this runs __init__
    try:
        while rclpy.ok() and not node.done:
            rclpy.spin_once(node)                        # let ROS 2 call on_pose when a pose arrives
    except KeyboardInterrupt:                            # this happens when you press Ctrl+C
        node.publisher.publish(Twist())
        print('Stopped.')
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

When is feedback worth it?
    
If nothing disturbs the robot and the timing is exact, an open loop is simple and good enough. In the real world wheels slip, batteries sag and computers get busy. Feedback turns an unknown disturbance into a small error that is corrected on the next cycle. The price is a measurement and a few gains to tune. When you drive the robot arm in Tutorial C, the same pattern appears with joint angles in place of the turtle's pose.
